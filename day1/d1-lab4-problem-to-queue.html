Day 1

Lab 4, problem to queue

  • Length 80 minutes
Agent
Stack

Goal

Turn one log line into a failing test, and triage a backlog in list order into a queue for an agent.

Before you start

  • Your repo from labs 1 to 3 on main, open in PowerShell in its root, your route, and paper for the agent's mistakes.
  • The course kit in C:\course\kit. If yours is elsewhere, change the path in step 1.

Steps

  1. Load the backlog, dry run first. On route A or B, change C to your letter.

    The loader puts 15 issues in your tracker for triage in part 2. The dry run prints what it would do and changes nothing.

    powershell -ExecutionPolicy Bypass -File C:\course\kit\load-backlog.ps1 -Route C -DryRun
    powershell -ExecutionPolicy Bypass -File C:\course\kit\load-backlog.ps1 -Route C

    The real run ends with Summary: 15 issues created. On routes A and B the label counts add up to 7.

Part 1, a test for the log line

  1. Part 1. Make a branch for the test. It never goes onto main.

    The test fails on purpose, so it stays on its own branch and the check on main stays green.

    git switch -c repro/log-line

    The agent starts from the log line alone and proves the bug with a test that fails because of it. Name no file, even if asked. The agent should find it.

    Type /clear, in Copilot CLI if you use VS Code. Send your stack's prompt.

    Python 
    The nightly member job stopped last night. Find out why, but do not fix it. Write a test that fails because of this bug, run it, and show me it fails for that reason. The last line of its log was: ValueError: salary for member M940217 is not a decimal
    .NET 
    The nightly member job stopped last night. Find out why, but do not fix it. Write a test that fails because of this bug, run it, and show me it fails for that reason. The alert showed only this line: Unhandled exception. System.FormatException: The input string '41,250.00' was not in a correct format.

  2. When the agent stops, run your check command.

    The check shows whether the new test fails, and fails for the right reason.

    powershell -ExecutionPolicy Bypass -File scripts\check.ps1; $LASTEXITCODE

    Only the new test fails, with the error type from the log line. The member may differ.

  3. Commit the test on the branch. Go back to main only if the commit worked.

    The commit keeps the failing test on its branch, ready for Day 2 to fix the bug.

    git add tests; git commit -m "Add a failing test for the bad salary"
    git switch main

Part 2, triage

  1. Part 2. On routes A and B, read your lab 3 CI run.

    Each push in lab 3 started a run of the check job on GitHub. The list shows those runs and whether each one passed.

    gh run list --workflow ci.yml --limit 3

    Tell the trainer if it failed.

  2. Type /clear, then start triage.

    Triage gives each issue a state and a reason, so the ready ones form a queue an agent can take. The skill recommends, and applies nothing until you agree.

    In reply, send Agreed. Apply it and go on to the next issue. or Take your recommended answers. Answer other questions with its advice. Stop at 5 ready and 1 record, or after the seventh issue.

    /triage Triage the backlog one issue at a time, oldest first. Recommend a category and a state for each, then wait for my decision.

  3. Read git status --short, then commit what triage wrote.

    Triage writes into the repo: the out of scope record on every route, and the issues as well on route C.

    git add ('.scratch','.out-of-scope' | ? { Test-Path $_ }); git commit -m "Triage the backlog"

    Line ending warnings are normal.

    Routes A and B: then push, so the triage comment links work.

    git push

The artefact you leave in the repo

  • On repro/log-line, a test that fails because of the bug. Nothing is fixed.
  • On main, triaged issues with a state and a reason, up to 5 ready with a brief, 1 record in .out-of-scope.

Done check

These show that the test still fails on its branch, that main passes, and what triage left. Routes A and B use gh, and route C uses sls.

git switch repro/log-line; powershell -ExecutionPolicy Bypass -File scripts\check.ps1; $LASTEXITCODE
git switch main; powershell -ExecutionPolicy Bypass -File scripts\check.ps1; $LASTEXITCODE
gh issue list --label ready-for-agent --search sort:created-asc
sls "^Status:" .scratch\backlog\issues\*.md -List | group Line -NoElement
Get-ChildItem .out-of-scope

The last line is not 0 on the branch and is 0 on main. Done is 5 ready and 1 record, or 7 triaged. Finished early? Stretch goals: d1-stretch-goals.html.

If you are stuck

  • If the agent fixed the bug, undo its changes outside tests, keep the test and run the check. The undo also deletes any untracked file you made outside tests, so move a file you want to keep first.
git restore --staged --worktree -- . ':!tests'; git clean -fd -- . ':!tests' ':!.scratch'
  • If the test passes, or fails for another reason, send Make it fail because of the bug. If the check shows 0, ask the agent to put the test where the check runs it.
  • If the loader on route A or B fails for two minutes, use route C. Run step 1 with -Route C, then Copy-Item .claude\skills\setup-matt-pocock-skills\issue-tracker-local.md docs\agents\issue-tracker.md.
