Goal

Drive the agent in your own repo, decide each time it asks to act, and turn its memory off.

Before you start

Install the GitHub CLI and sign in to your own GitHub account.

This morning's machine check needed gh too. If you set it up only now, tell the trainer. Keep the route your check printed unless the trainer moves you in the break.

The labs use gh, the GitHub CLI. Check it first. If the check lists your own account with Active account: true, you are ready.

gh auth status

If PowerShell does not find gh, install it.

winget install --id GitHub.cli --exact --source winget

When the install ends, open a new PowerShell window, so it finds gh. In the new window, go back to the course folder.

cd C:\course

If the check does not list your account, sign in with your own account and follow the prompts. Then run the check again.

gh auth login --hostname github.com --git-protocol https --web

If the install or the sign in fails, ask the trainer.

Part 1, one question about the code

  1. Part 1. Start a session and ask one question about the code.

    Start the agent in the repo folder. When it asks whether you trust this folder, say yes. You cloned it.

    Claude Code 
    claude
    GitHub Copilot

    In VS Code, run code . and start a New Chat on the Copilot harness instead.

    copilot

    Type this question at the agent's prompt. It shows whether the agent reads the repo before it answers. Expect a short list of paths, each with the group that owns it.

    Which paths in this repo need a review from another group before they change, and which group owns each? Answer in a short list.

    A good answer names the file it read. Note a vague or wrong answer as a mistake.

Part 2, one permission prompt

  1. Part 2. Answer the permission prompt Yes. This request is sure to prompt.

    You decide each time the agent asks to act. Check what will change, whether it stays in this repo, and whether you can undo it. Never pick "Yes, and don't ask again". In VS Code, Allow is one yes.

    Create a file named scratch.txt in the repo root that holds the word hello.

Part 3, memory off

  1. Part 3. Switch memory off and check it.

    Automatic memory carries a preference from one conversation into every later one, so Pocock turned his off. A preference belongs in a file in the repo instead.

    Leave a CLI agent with /exit and run Remove-Item scratch.txt. Switch memory off with your agent's commands. The last command prints your settings file, with memory set to false. When the timer ends, show the settings file.

    Claude Code 
    New-Item -Force .claude\settings.json -Value '{"autoMemoryEnabled": false}'
    git add .claude/settings.json
    git commit -m "Turn agent memory off"
    Get-Content .claude\settings.json
    GitHub Copilot

    In VS Code, set "chat.copilot.memory.enabled": false instead.

    copilot config memory false
    Get-Content "$env:USERPROFILE\.copilot\settings.json"

The artefact you leave in the repo

  • Claude Code. .claude/settings.json holds "autoMemoryEnabled": false, and it is committed.
  • GitHub Copilot. Your user settings hold "memory": false, or the VS Code setting. Neither is in the repo.

Done check

Run the command for your agent. It shows whether memory is off.

Claude Code 
claude -p "Reply with your auto memory directory, or NONE if it is off." --tools=

It prints NONE.

GitHub Copilot

In VS Code, show the setting instead.

copilot config memory

It prints false.
