Stretch goals, Day 1

  • Two goals for each lab
  • About 5 to 15 minutes each
Lab

Stack

Take a goal once you meet your lab's done check. The second goal is the harder one. Stop when the trainer calls the room back, and do its put back line, so the next lab finds your repo as it expects. Start each goal in a fresh session: /exit and start again, or a New Chat in VS Code. The prompts suit both agents. Note the agent's mistakes on your paper. The check is powershell -ExecutionPolicy Bypass -File scripts\check.ps1; $LASTEXITCODE.

Lab 1, drive the agent

1. Yes to what reads, No to what deletes

Make an untracked file with Set-Content notes.txt 'my notes', then send the prompt. Judge each command the agent asks to run. Does it change a file? Does it stay in this repo? Can you undo it? Git holds no copy of an untracked file, so its delete cannot be undone. Say Yes to a command that only lists. Say No to any delete, also when it tries another command for the same delete. Write each command, your answer and why on your paper.

Remove every file in this repo that git does not track.

Done when Test-Path notes.txt prints True and your paper lists each command with Yes or No and a reason. Put back. Run Remove-Item notes.txt -ErrorAction SilentlyContinue. If a Yes deleted more than that file, tell the trainer.

2. Ask it to remember, with memory off

Send the first prompt. Memory is off, so the agent may ask to hide a file from git or to write one that later sessions read. Claude Code may ask for CLAUDE.md. Copilot may ask for .github\copilot-instructions.md. Say No, as the later labs expect no such file. Then send the second prompt in a fresh session.

Remember for all future sessions in this repo: I want every answer as one short list.
How do I want answers in this repo? Reply in one line.

Done when the new session does not know, and Test-Path CLAUDE.md, CLAUDE.local.md, .github\copilot-instructions.md; git status --short prints False three times and nothing else. Put back. Delete any file it wrote with Remove-Item, and any line it added in notepad .git\info\exclude.

Lab 2, one-command build and test

1. What does a pointer save?

Send the prompt. Note the file it names and how many files it opens. Then move AGENTS.md out of the repo, start a fresh session and send the same prompt. Note the same two things. Expect the same answer both times, found in one step with the pointer and after several files without it. That saved search is what the pointer earns.

How do I build and test this repo? Answer in one line, name the file that told you, and run nothing.
Move-Item AGENTS.md $env:TEMP\AGENTS.md

Done when your paper holds both answers, the files each one opened, and whether the pointer earns its line. Put back. Run Move-Item $env:TEMP\AGENTS.md . -ErrorAction SilentlyContinue. Then Test-Path AGENTS.md prints True.

2. Does the agent check its own work?

The prompt does not say how to check. Say Yes when the agent asks to run scripts\check.ps1. If it runs another test command, note a mistake and ask which command AGENTS.md gives.

Add a one-line comment at the top of the unit test file with the most tests, saying what it tests. Make sure nothing is broken.

Done when the agent ran scripts\check.ps1 unasked, it ended with 0, and one test file changed. Put back. Run git restore tests.

Lab 3, rules become checks

1. Which layer catches it?

Run the blocks in order. Plant a banned date call in a new file, stage it and run your hook without a commit, then run the check. Note which fails. Then swap that fault for spaces at the end of a line, and run the hook block and the check again. The answers depend on the hook you kept in lab 3. CI catches what the check catches.

Python 
'from datetime import datetime', 'parse = datetime.strptime' | Set-Content src\stretch.py
.NET 
@(
'namespace MemberIngestion;'
''
'internal static class Stretch'
'{'
'    internal static DateOnly Day() => DateOnly.Parse("01/02/2026");'
'}'
) | Set-Content src\MemberIngestion\Stretch.cs
git add -A; powershell -ExecutionPolicy Bypass -File scripts\pre-commit.ps1; $LASTEXITCODE
git reset -q; git clean -fq src; Add-Content README.md 'Ends in spaces.   '

Done when your paper has a row for each fault with the layer that caught it, the hook, the check or none, and why that layer is right or wrong. Put back. Run git reset -q; git restore .; git clean -fq src, wherever you stopped.

2. Break a boundary and let the agent find it

Add a dependency that points upwards and run the lab 3 boundary check. It fails. The prompt names no file. The agent will ask to run the boundary check. Say Yes.

Python 
Add-Content src\valuation_extract\__init__.py 'import employer_reports'
$env:PYTHONPATH = "src;vendor;."; lint-imports
.NET 
'namespace MemberIngestion.Members;', 'internal static class S { internal static Type K() => typeof(Reports.JoinersReport); }' | Set-Content src\MemberIngestion\Members\S.cs
dotnet test tests/MemberIngestion.UnitTests --filter FullyQualifiedName~ArchitectureTests
The boundary check fails. Find the dependency that breaks it and say why it is not allowed, in two lines. Change no file.

Done when the agent names the line you added and the layer rule it breaks, and changed nothing. Put back. Run git restore src; git clean -fq src. The check then ends with 0.

Lab 4, problem to queue

1. Argue with your own triage

On a clean main, pick the issue you triaged with the least certainty, and write its state and your reason on your paper. Send the prompt with that issue's title typed after the last word. The agent argues from the issue's words alone. Say No to any command that changes an issue.

Read only the issue whose title follows, in this repo's issue tracker. Open no other file, no code and no other issue, and run no command except one that reads that issue. Using only the words of that issue and the five triage states, needs-triage, needs-info, ready-for-agent, ready-for-human and wontfix, give the strongest case for a state other than its current one. Then say whether you would keep its current state, and why. Name no other issue, and suggest no cause and no fix. Change nothing. The title:

Done when your paper holds your state and reason, the agent's case against it, and whether you keep your state and why. Note a change you want on paper and leave the tracker as it is. Put back. Run git restore .; git clean -fq .scratch .out-of-scope. It removes only what changed in the goal, never your committed triage.

2. Red for the wrong reason

Spoil the test on the test branch, run the check, and read why it is red. Send the prompt, and say Yes when the agent asks to run the tests. Then run git restore tests and the check again.

git switch repro/log-line; $t = git diff --name-only main -- 'tests/*.py' 'tests/*.cs' | select -First 1; Add-Content $t 'broken here'
Does the failing test on this branch fail because of the bug it was written for, or for another reason? Prove it from the test output. Change no file.

Done when the agent said the spoilt test fails for another reason and quoted that error, then the restored test fails with the log line's error. Put back. Run git restore tests; git switch main.
