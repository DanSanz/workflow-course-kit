Skill card

writing-for-agents

  • Learning outcome 1: Make a repository agent-ready: one-command checks, skills at project scope, AGENTS.md as pointers, a glossary and a standards file.

The pain point

A bloated AGENTS.md and bloated skills waste context. Matt Pocock says: "pulling it out into skills to stop that horrible frontloading". Agents also write long instructions, and most of the words explain what the model already knows.

What the skill does

It is a reference for writing any document an agent reads: a skill, an AGENTS.md or CLAUDE.md file, or a doc your AGENTS.md points to. It helps you find the lines that cost context and change no behaviour. It guides you in moving material out of AGENTS.md into skills, and writes nothing itself. The aim is a more concise document and more predictable output.

When to skip it

  • You are writing a document that no agent reads. The skill is for documents an agent reads.
  • You want to know what a codebase contains. The skill is for how a document reads, not for what it knows.

Where the course uses it

  • Day 1, 10:45, lab 2, one-command build and test. You write AGENTS.md as short pointers to other docs.
