Alternatives card

Make the repository ready for agents

  • Workflow step: S1
  • Slot: Day 1, in the 13:15 block

Pocock's way

Pocock keeps standing instructions small and moves checkable rules into the build.

  • A short AGENTS.md. It holds only what the agent cannot find by looking. The setup skill adds pointers, not content.
  • Standards and a glossary in their own files. Review agents read the standards file, docs/standards.md in the lab. GLOSSARY.md gives each term a definition and an Avoid line.
  • Fast checks at commit, slow checks in CI. A pre-commit hook runs the quick checks, ideally in under 3 seconds. CI runs the rest before merge. Per-edit harness hooks are slow and noisy.
  • Repeated mistakes become checks. A review of one repo found a check script that nothing ran, and suggested a CI pipeline. In the lab, one banned-API rule finds the hand-rolled date parses.
  • Deep modules. A small interface lets the agent use a module without reading it. A boundary check keeps modules apart.

What poteto does instead

poteto encodes lessons in types and lint before prose. "The best rules are in your code."

  • Each review comment becomes a hard rule. poteto turns it into a lint rule, a CI failure or a design that removes the problem. A rule only a human enforces is "a code smell".
  • Lint rule first, cleanup after. Add the rule so a bad pattern stops spreading. Then agents fix the old cases. One rule bans useEffect and CI fails on it.
  • Instruction files are a soft layer. Nothing fails when an agent skips a written rule. Soft layers alone end in "complete trash".
  • Evals. An eval checks each skill change.

What Theo does instead

Theo hand-writes a short AGENTS.md in his own voice. Agent failures become evals before the instructions change.

  • A letter, not a rulebook. It says how we think and why, with few rules and no file paths. Generated agent files make models worse.
  • What goes in. T3 Code's file holds a glossary of "you", "we" and "users", checklists and a taste section.
  • One file for every tool. CLAUDE.md imports AGENTS.md, with Claude-only lines below.
  • What his evals test. An eval of the times models misused T3 Code's tools let him cut their descriptions to a third.

Which target would justify switching

At this step the targets differ on how much a team puts into skills, rules and checks.

  • Pocock's way fits the targets Planned backlog delegation and Risk-tiered platform. Both install one skill set per project. The second also uses poteto's way.
  • Switch to poteto's way if your target is Environment-first autonomy. It needs a funded platform team and code that can be constrained. It costs up-front work on the environment, and eval runs cost tokens.
  • Switch to Theo's way if your target is Evidence-gated agent merge. It needs fast CI, a staged release, a quick revert and senior engineers who judge evidence. The cost is fewer checks the whole team shares, unless failures move into the architecture, lint or CI. Supervised pairing uses a short hand-written file.
